# Explicit Acoustic Peer Identity Summary

The runner now makes the FAS1 peer identity explicit instead of the browser
deriving a fixed `fipwave-a`/`fipwave-b` pair from its role.

## Delivered

- Added `peerMachineId` to the production-runner API, CLI, immutable public
  configuration, and browser schema.
- Passed that exact value into `AcousticSession.expectedPeer`, so HELLO
  validation works with the documented `laptop-a` / `laptop-b` identities.
- Kept the previous role-derived names only as a compatibility default for
  callers that do not provide a peer identity.
- Updated both two-laptop and single-laptop self-loop runner commands to use
  reciprocal identities.
- Added a production-browser regression that asserts a `laptop-a → laptop-b`
  configuration reaches `/qualification-config` unchanged.
